# Заявки в каталоги офисных продуктов

Этот документ описывает подготовку и отправку Tishte владельцам офисных
продуктов. Пакет является надстройкой над релизом v1.100 и не изменяет
опубликованные шрифтовые файлы, заявки Google Fonts или регистрацию Microsoft.

## Приоритет

1. Р7-Офис — технически наиболее прямой путь для настольного и серверного
   продукта.
2. МойОфис — стратегическая заявка через технологическое партнёрство.
3. AlterOffice — запрос на включение в поставляемый набор свободных шрифтов.
4. LibreOffice — enhancement, обсуждение с разработчиками и при необходимости
   патч упаковки.
5. Офис+ и Яндекс Документы — обращение к команде продукта или партнёрств.
6. ONLYOFFICE — международный дополнительный канал.

Актуальные маршруты хранятся в `partner-kit/contacts.json`, тексты обращений —
в `partner-kit/letters/`.

## Сборка комплекта

Сначала должны существовать официальные релизные архивы v1.100 в `dist/`.

```powershell
python scripts/build_partner_submission_kit.py --version 1.100
python scripts/audit_partner_submission_kit.py --version 1.100
```

Результат:
`build/publishing/submissions/Tishte-v1.100-office-suite-kit.zip` и файл его
SHA-256. Сборщик берёт бинарники непосредственно из двух релизных ZIP и не
перекомпилирует шрифты.

Контрольные DOCX, XLSX, PPTX и ODT при необходимости пересоздаются в Windows с
установленным Microsoft Office:

```powershell
.\scripts\Build-OfficeSuiteSamples.ps1
```

Генератор заново открывает созданные документы, пересчитывает книгу Excel и
делает PDF/PNG в `build/partner-kit-qa/` для визуальной проверки. QA-файлы в
итоговый ZIP не включаются.

## Порядок отправки

1. Перед отправкой проверить адрес, форму и условия обработки данных на
   официальном сайте получателя.
2. Заменить `{{PRODUCT}}`, `{{PACKAGE_LINK_OR_ATTACHMENT}}`, `{{EMAIL}}` и
   `{{PHONE}}` в выбранном шаблоне.
3. Прикрепить один общий ZIP либо дать ссылку на неизменяемый релизный артефакт.
4. Сохранить дату, номер обращения, адресата и полученный ответ.
5. Не обещать изменение метрик, имён семейств или лицензии без отдельной оценки:
   такие изменения потребуют нового релиза и уведомления действующих площадок.
